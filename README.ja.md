# 推し活マネージャー

[简体中文](README.md) · [English](README.en.md) · **日本語**

<img src="assets/icon-only.png" alt="推し活マネージャーのアイコン" width="96" />

日本のライブ・イベントの抽選、先行受付、一般発売をまとめて確認できるアプリです。アーティストを検索し、公演をお気に入りに登録して、各受付の日時を確認したり、端末にリマインダーを設定したりできます。

[Android APK をダウンロード](https://github.com/aoki-rin/oshikatsu-manager/releases/latest) · [iOS のビルド・インストール手順](docs/BUILDING.md#ios) · [不具合を報告](https://github.com/aoki-rin/oshikatsu-manager/issues) · [MIT ライセンス](LICENSE)

## ダウンロードとインストール

[v1.1.3 の更新内容](docs/releases/v1.1.3.md)：別公演の誤った統合、eplus の公演欠落、カレンダーの締切時刻、ローチケの複数公演日、ぴあの混雑時の案内を修正しました。既存のお気に入りやリマインダーの互換性にも対応しています。

### Android

1. 上のダウンロードリンクを開き、**Assets** から `oshikatsu-manager.apk` をダウンロードします。
2. スマートフォンで APK を開き、必要に応じてその提供元からのインストールを許可して、インストールします。
3. 通知を使う場合は通知権限を許可し、端末のアラーム・リマインダーやバッテリー制限の設定を確認してください。

アカウント登録、常時起動するパソコン、サーバーの用意は不要です。5 つのチケット情報源に対応するプラグインはすべて内蔵されており、別途ダウンロードする必要はありません。公式 APK はスマートフォンのネットワークから各チケットサイトに直接接続します。開発者のパソコン、プロキシ、Tailscale に依存せず、パソコンの電源が入っていなくても使えます。

Android 7.0（API 24）以降が必要です。ローチケの検索には Google Play 開発者サービス版の Cronet を使用しています。Google Mobile Services（GMS）のない端末での動作は未検証です。サイトの変更やネットワーク側の制限によって検索できない場合は、アプリから公式のチケットページを開いて確認できます。

更新時は、このリポジトリから新しい APK をダウンロードして上書きインストールしてください。同じ署名の APK で更新できます。署名の不一致を解決するためにすぐアンインストールしないでください。お気に入り、フォロー、設定は端末内に保存されており、アンインストールやデータの消去で失われる場合があります。

### iOS

ソースコードと [Xcode でのビルド・インストール手順](docs/BUILDING.md#ios)を公開しています。**現在、TestFlight の招待リンクや、誰でも直接インストールできる IPA は提供していません。** Mac、Xcode、ご自身の Apple アカウントによる署名が必要です。IPA を GitHub に置くだけでは、Apple の署名や端末認証の要件はなくなりません。[Apple の配布に関するドキュメント](https://developer.apple.com/documentation/xcode/distributing-your-app-for-beta-testing-and-releases)も参照してください。

## 機能と制限

- eplus（イープラス）、チケットぴあ、ローチケ、LivePocket、TicketDive を検索できます。
- アーティストのフォロー、推しカラーの設定、公演のお気に入り登録に対応し、カレンダーや公演詳細から受付期間を確認できます。
- 取得できた複数回の抽選・先行受付・一般発売の日時を、日本標準時（JST）で表示します。
- Android / iOS のローカル通知に対応しています。Android とブラウザーでは `.ics` 形式でカレンダーに書き出せます。iOS では現在、書き出し機能を非表示にしています。
- アプリの表示言語は中国語と日本語に対応しています。各チケット情報源は個別に有効・無効を切り替えられます。
- 情報の確認とリマインダーを補助するアプリです。申し込みや支払いは公式サイトで行ってください。情報源によって取得できる内容が異なり、サイトの変更、アクセス制限、端末の通知設定などの影響を受けます。最終的には公式ページの情報をご確認ください。

本プロジェクトはソフトウェアを公開するもので、公開プロキシサービスや各チケットサイトへの継続的な接続を保証するものではありません。検索頻度に配慮し、各サービスの利用規約を守ってご利用ください。

## ソースコードから起動する：ブラウザープレビュー

**Node.js 22.22.1 以降、npm、Git** を用意してください。Android / iOS の開発環境は、スマートフォン用アプリをビルドする場合にのみ必要です。`.nvmrc` があるので、nvm をお使いの場合は先に `nvm install` と `nvm use` を実行できます。

```bash
git clone https://github.com/aoki-rin/oshikatsu-manager.git
cd oshikatsu-manager
npm ci
cp .env.example .env
```

Windows PowerShell では最後の行を `Copy-Item .env.example .env` に置き換えてください。GitHub の **Code → Download ZIP** からダウンロードして展開し、プロジェクトのディレクトリに移動する方法もあります。

ターミナルを 2 つ開き、どちらもプロジェクトのディレクトリに移動します。

```bash
# ターミナル 1：ローカルのチケット情報プロキシ（既定では 127.0.0.1:8787 のみで待ち受け）
npm run server:dev
```

```bash
# ターミナル 2：Web 開発サーバー
npm run dev
```

**http://localhost:3000** を開いてください。ブラウザー開発では、Vite が検索リクエストをローカルプロキシへ転送するため、Web サーバーだけを起動しても検索は利用できません。チケットサイト側でアクセスが制限される場合もあります。通知など OS に関わる機能は実機で確認してください。

## スマートフォン用アプリのビルド

環境の準備、デバッグ、署名、インストールの詳細は[ビルドガイド](docs/BUILDING.md)を参照してください。リンク先の詳細ドキュメントは、現在主に中国語で記載されています。Android の開発用 APK は、開発者の署名鍵なしでビルドできます。

```bash
npm run build:release
npx cap sync android
cd android
./gradlew assembleDebug
```

Windows では `gradlew.bat assembleDebug` を使用します。生成先は `android/app/build/outputs/apk/debug/app-debug.apk` です。事前に JDK 21 と Android SDK 36 をインストールし、SDK のパスを設定してください。詳細はビルドガイドをご覧ください。

## 設定

| 利用方法 | 設定と起動方法 |
|---|---|
| 公式 APK をダウンロードして使う | スマートフォンからの直接接続を設定済み。`.env` は不要 |
| ブラウザーで開発する | `.env` の値を空のままにして、`server:dev` と `dev` を両方起動 |
| 直接接続するスマートフォン用アプリをビルドする | `npm run build:release` を実行し、ネイティブプロジェクトを同期 |
| 自分のプロキシを使うアプリをビルドする | `.env` に `VITE_TICKET_PROXY_BASE_URL` を設定し、`npm run build` 後にネイティブプロジェクトを同期 |

プロキシには、スマートフォンから接続できる HTTPS の URL を指定してください。設定した場合は各情報源への接続でプロキシを優先し、失敗するとクライアントからの直接接続を試みます。ブラウザーからの直接接続は CORS によって制限される場合があります。

**`VITE_` で始まる設定値はアプリに組み込まれます。パスワードや秘密鍵などを含めないでください。** 設定を変更したら、ビルド、同期、インストールをやり直してください。`build:release` は `.env` を読み込まず、プロキシ URL を明示的に空にするため、ローカルの設定ファイルを移動・削除する必要はありません。

## よくある質問

**ブラウザーで検索できない場合は？** `npm run server:dev` が起動していることを確認し、アプリで該当する情報源のエラーを確認してください。アクセス制限、サイトの変更、ネットワークの問題は、それぞれ切り分けが必要です。

**スマートフォンが個人用プロキシに接続するのはなぜ？** 開発用ビルドに、ビルド時の `.env` の値が含まれている可能性があります。`npm run build:release` を実行してから、再度 `cap sync` とインストールを行ってください。

**Android でインストールできない、または署名が一致しない場合は？** デバッグ版、第三者がビルドした版、公式 APK では署名が異なることがあり、そのまま上書きできません。まず既存のデータを保護し、入手元と署名を確認してください。すぐに既存アプリをアンインストールしないでください。

**macOS のビルドで `code signature ... different Team IDs` と表示される場合は？** Node の署名制限によって、ビルドに必要なネイティブモジュールを読み込めない場合があります。Homebrew などの通常の Node インストールに切り替え、`npm ci` を再実行してください。
